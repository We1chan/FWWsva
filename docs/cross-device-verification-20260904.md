## 2. 本轮发现并处理的跨设备问题

- 本机数据库的设备菜单仍指向 `device/index`，与新前端 `device/manage` 不一致。
  数据库备份后，仅切换已确认的菜单组件字段，保留路径、父菜单与权限。
- 旧数据库缺少部分新字段；使用增量迁移，不用全量初始化 SQL 覆盖业务数据。
- 示例设备组织与用户可见部门不同会导致列表看不见设备；组织归属改为可配置并与国标同步一致。
- Vue CLI 代理前缀会进行非锚定匹配，`/live` 可能误匹配 `/media/live`；代理规则已限定路径开头。
- WVP 公布的 LAN 媒体地址在 WSL 内可用，不代表 Windows 浏览器可以连接。
  前端增加显式 `VUE_APP_GB_MEDIA_PUBLIC_ORIGIN`，仅将指定实例代理到同源 `/gb-media`。
- 浏览器预览关闭后原来只暂停播放器，错误状态会被带到下一次打开；现已释放实例，
  重开创建新解码状态，并合并 URL/可见性监听器的重复初始化。连续切换两类源已复验。
- FFmpeg 编码器按实际能力选择：CPU 使用 libx264，NVENC 必须通过能力测试才选用；不把个人显卡设置硬编码到共享脚本。
- GB 软件相机读取环境文件后再确定服务器地址，支持独立 SIP 端口；补丁保持 LF 换行。
- 模型安装验证文件摘要并保留原模型备份，不自动启动高负载推理。

本机路径、数据库凭据、IP 与 WSL 发行版留在本地配置，不随共享代码推送给协作者。
收尾时协作者补充了国标重连后重建算法控制的提交 `f7b45ab`，本轮也已审核、合入、
重新测试和编译；安装器保留这一后端更新，同时锁定本轮前端预览修复版本。

## 3. CPU 能否运行模型

本机可以运行 CPU 推理：姿态 ONNX 的 30 帧测量耗时约 12.62 秒，约 2.38 FPS；
CPU Analyzer 成功加载姿态和眼部模型，单路 1 FPS 短时任务运行约 20 秒后正常停止。
这证明模型和 CPU 推理链路可启动，不等于已经验证完整睡岗告警准确率或长时间稳定性。

本机默认只启动平台、流媒体、WVP 和软件相机，AI 分析器关闭；四个睡岗演示任务不自动运行。
需要体验模型时，先只运行一条 1 FPS 任务。没有验证四路并行 AI 性能，也没有验证 NVIDIA
驱动、CUDA/cuDNN、GPU provider 或 GPU 推理速度，这些需在协作者的 NVIDIA 电脑复验。
国标点播/预览测试不要求启动 AI。

## 4. 本机复验步骤

1. 运行工作区根目录的 `启动本机easySVA.ps1`，等待显示 `easySVA is ready.`。
   脚本仅适用于当前电脑；其他电脑使用跨设备指南的部署入口。
2. 打开 `http://127.0.0.1:8080`，登录后进入“视频智能分析 → 设备管理”。
3. 点击“同步国标设备”，查看接入类型、国标设备 ID 与通道 ID；同步名称可能都为 `ch1`，
   用 ID 区分 test3（设备尾号 00003、通道尾号 00013）和 test6（00006、00016）。
4. 点击“启动视频源 → 预览视频”。画面和播放时间应持续变化，不能只以成功提示作为标准。
5. 关闭预览，点击“停止视频源”，再次预览国标设备应被拒绝。
6. 验收离线时停止对应软件相机进程，不是仅停止视频源；等待心跳超时后同步。
   然后重启软件相机，确认恢复在线并重新预览。
7. 对一台 RTSP 设备重复启动、预览、停止，验证旧链路不受影响。

“启动视频源”只控制取流；“布控任务”才启动算法。不要为了验收点 3 同时启动所有 AI 任务。

## 5. 保留的限制与告警

- 使用软件相机完成协议链路复现，没有实体 IPC 的厂商兼容性测试。
- 最终启动后的健康检查全部通过，SIP TCP/UDP 5060 均在监听；软件相机实际使用 UDP。
  早前 TCP 曾受 Windows 排除端口影响，不能把“最终监听成功”表述为完成 TCP 相机实播测试。
- 前端包体积、Browserslist 数据版本、既有依赖/API 过时告警仍存在；构建成功不等于没有性能优化空间。
- 开发服务器 HMR 的 LAN 地址连接问题与媒体地址分开记录，不代表前端生产构建或已验证媒体取流失败。
- 测试、构建、迁移与实流验证分别执行；不把中途服务重启时失败的单次整套回归命令表述为全部通过。

数据库升级前已保存本地 SQL 备份。后续拉取协作者代码时继续保留本机配置，先检查增量迁移，
不要直接照搬 GPU 部署命令，也不要对已有数据库重复执行全新安装器。
