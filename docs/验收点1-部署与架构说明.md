# 验收点 1：部署与架构说明

## 当前部署基线

- 环境：WSL2，Ubuntu 22.04 LTS，systemd。
- Web：Nginx + Vue，默认地址 `http://localhost/`。
- 业务服务：Spring Boot，端口 `9114`。
- 数据：MariaDB（数据库 `easySVA`）和 Redis。
- 流媒体：ZLMediaKit，HTTP 端口 `9992`，RTSP 端口 `9994`。
- 分析服务：Analyzer，管理端口 `9993`，GPU 版 ONNX Runtime 1.26.0（CUDA 13 / cuDNN 9，CPU 自动回退）。
- 模型：`yolo11n.onnx`、`yolo26s.onnx`，均取自项目提供的 `Analyzer-lib.zip`。
- 模拟摄像头：FFmpeg 将仓库目录下的 `test1.mp4` 循环推送到 `rtsp://127.0.0.1:9994/live/mock-camera`。

## 调用关系

```text
                                      └── 告警回传 SVA-backend :9114
```

## 服务管理

服务由 systemd 管理：

- `easysva-backend.service`
- `easysva-media.service`
- `easysva-analyzer.service`
- `easysva-rtsp-simulator.service`（无实体摄像头时使用）
- `easysva-stream-restore.service`（ZLM 重启后恢复处于 RUNNING 状态的直连设备代理）
- `nginx.service`
- `mariadb.service`
- `redis-server.service`

查看总状态：

```bash
systemctl --no-pager --full status easysva-backend easysva-media easysva-analyzer nginx mariadb redis-server
```

如果数据库显示设备为 `RUNNING`，但 ZLMediaKit 因 WSL 关闭而丢失了内存中的拉流代理，可执行：

```bash
sudo systemctl restart easysva-stream-restore
sudo journalctl -u easysva-stream-restore -n 50 --no-pager
```

一键启动脚本会自动执行这一步。候选视频源清单位于 `deploy/sample-streams.tsv`；其中公网 HLS 地址需要以实际拉流和解码结果为准，验收现场建议使用本地 RTSP 模拟源。

查看日志：

```bash
journalctl -u easysva-backend -u easysva-media -u easysva-analyzer -f
```

## 验收操作

1. 浏览器打开 `http://localhost/`，使用 `admin / admin123` 登录。
2. 在设备管理中确认设备“模拟RTSP摄像头”，其 RTSP 地址为 `rtsp://127.0.0.1:9994/live/mock-camera`，点击“预览视频”。
3. 在布控管理中确认任务“验收点1-YOLO模拟检测”处于 `RUNNING`；算法为 `yolo11n_80`，目标为 `person`，检测区域覆盖全画面。
4. 确认画面出现 person 检测框，并收到“停留告警”；进入报警管理检查告警图片。
5. 保存页面、服务状态、预览和告警截图作为验收材料。

## GPU 验证

WSL 使用 Windows 提供的 NVIDIA 驱动，WSL 内只安装 CUDA 用户态运行库、cuDNN 和 GPU 版 ONNX Runtime。不要在 WSL 内安装 Linux 显卡驱动。

```bash
# 驱动和 GPU 是否透传到 WSL
nvidia-smi

# 服务是否使用 GPU 二进制及运行库
systemctl cat easysva-analyzer

# 必须能看到 CUDAExecutionProvider、appended CUDAExecutionProvider 和 provider=CUDA
journalctl -u easysva-analyzer -b --no-pager | \
  grep -E 'CUDAExecutionProvider|provider=CUDA'

# GPU 版 ONNX Runtime 的 CUDA 依赖应全部解析，不应出现 not found
LD_LIBRARY_PATH=/usr/local/onnxruntime-gpu/lib:/usr/local/cuda-13.1/lib64:/opt/SVA/cudnn/nvidia/cudnn/lib:/usr/lib/wsl/lib \
  ldd /usr/local/onnxruntime-gpu/lib/libonnxruntime_providers_cuda.so | grep 'not found'
```

当前 GPU 运行库位置：

- CUDA 13.1：`/usr/local/cuda-13.1/lib64`
- cuDNN 9：`/opt/SVA/cudnn/nvidia/cudnn/lib`
- ONNX Runtime GPU 1.26.0：`/usr/local/onnxruntime-gpu`

自动选择结果可通过以下命令查看：

```bash
journalctl -u easysva-analyzer -b --no-pager | grep '\[easySVA\]' | tail
```

无 NVIDIA GPU、驱动不可用、GPU 二进制缺失或 CUDA/cuDNN 依赖不完整时，启动器都会记录原因并自动运行 CPU Analyzer。

从零运行 `install_source.sh` 时，选择 GPU 模式会分别安装 `/usr/local/onnxruntime`（CPU）和 `/usr/local/onnxruntime-gpu`（GPU），并分别生成 `Analyzer.cpu`、`Analyzer-gpu`；选择 CPU 模式只生成 CPU 版本。部署阶段会安装启动器及 `easysva-backend`、`easysva-media`、`easysva-analyzer` 三个 systemd 服务，不再通过 `rc.local` 重复启动进程。

TensorRT 是可选加速器。当前环境未安装 TensorRT，Analyzer 尝试加载失败后会自动选择 CUDA，不影响 GPU 推理和报警链路。

## 说明

WSL 中不安装压缩包内附带的 Linux NVIDIA 驱动。当前机器由 Windows 驱动 616.56 提供 GPU 透传，Analyzer 使用 CUDA 推理；如果 CUDA Provider 初始化失败，程序仍会回退到 CPU Provider，保证服务可启动。

双击 `关闭easySVA.bat` 会先停止服务，再执行 `wsl --shutdown`，保证释放 `vmmemWSL`。由于 WSL 使用共享虚拟机，这也会停止其他 WSL 发行版和 Docker 的 WSL 后端。如果只想终止 easySVA、不要求释放 `vmmemWSL`，可在命令行执行 `关闭easySVA.bat --distro-only`。
