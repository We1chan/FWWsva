# 验收点 1：部署与架构说明

## 当前部署基线

- 环境：WSL2，Ubuntu 22.04 LTS，systemd。
- Web：Nginx + Vue，默认地址 `http://localhost/`。
- 业务服务：Spring Boot，端口 `9114`。
- 数据：MariaDB（数据库 `easySVA`）和 Redis。
- 流媒体：ZLMediaKit，HTTP 端口 `9992`，RTSP 端口 `9994`。
- 分析服务：Analyzer，管理端口 `9993`，CPU 版 ONNX Runtime 1.26.0。
- 模型：`yolo11n.onnx`、`yolo26s.onnx`，均取自项目提供的 `Analyzer-lib.zip`。
- 模拟摄像头：FFmpeg 将仓库目录下的 `test1.mp4` 循环推送到 `rtsp://127.0.0.1:9994/live/mock-camera`。

## 调用关系

```text
浏览器
  │ HTTP :80
  ▼
Nginx ───── /prod-api/、/websocket/ ─────► SVA-backend :9114
  │                                             │
  │                                             ├── MariaDB :3306
  │                                             └── Redis :6379
  │
  └── 静态页面、告警图片/录像

test1.mp4 ─► FFmpeg 模拟 RTSP 摄像头 ─► ZLMediaKit :9994 ─► Analyzer :9993
                                      │
                                      ├── ONNX Runtime + YOLO
                                      └── 告警回传 SVA-backend :9114
```

## 服务管理

服务由 systemd 管理：

- `easysva-backend.service`
- `easysva-media.service`
- `easysva-analyzer.service`
- `easysva-rtsp-simulator.service`（无实体摄像头时使用）
- `nginx.service`
- `mariadb.service`
- `redis-server.service`

查看总状态：

```bash
systemctl --no-pager --full status easysva-backend easysva-media easysva-analyzer nginx mariadb redis-server
```

查看日志：

```bash
journalctl -u easysva-backend -u easysva-media -u easysva-analyzer -f
```

## 验收操作

1. 浏览器打开 `http://localhost/`，使用 `admin / admin123` 登录。
2. 在设备管理中确认设备“模拟RTSP摄像头”，其 RTSP 地址为 `rtsp://127.0.0.1:9994/live/mock-camera`，点击“预览视频”。
3. 在布控管理中确认任务“验收点1-YOLO模拟检测”处于 `RUNNING`；算法为 `yolo11n_80`，目标为 `person`，检测区域覆盖全画面。
4. 确认画面出现 person 检测框，并收到“停留告警”；进入报警管理检查告警图片。
5. 保存页面、服务状态、预览和告警截图作为验收材料。

## 说明

WSL 中不安装压缩包内附带的 Linux NVIDIA 驱动。WSL 的 GPU 驱动由 Windows 提供；当前先使用 CPU 推理完成稳定验收链路，后续如切换 GPU，只安装匹配的 CUDA Toolkit、cuDNN 和 GPU 版 ONNX Runtime。
